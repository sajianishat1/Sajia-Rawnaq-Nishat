# How to publish your GitHub portfolio

You will create **four repositories**. Replace `YOUR-USERNAME` with your GitHub username everywhere (use find-and-replace in each file).

## 1. Profile README (shows on your GitHub profile page)

1. Create a **public** repository named exactly like your username (for example `sajia-nishat`).
2. Tick **Add a README file**, or upload `profile-readme/README.md`.
3. Visit `github.com/YOUR-USERNAME`; the README appears on your profile.

## 2. Portfolio website (GitHub Pages)

1. Create a **public** repository named `YOUR-USERNAME.github.io`.
2. Upload everything inside `portfolio-site/`: `index.html` and the `assets/` folder.
3. Copy your CV PDF into `assets/` and keep the file name `CV_Sajia_Rawnaq_Nishat.pdf` (the Download CV button points to it). Consider removing your phone number and your references' phone numbers from the public copy.
4. In the repository go to **Settings → Pages**, choose **Deploy from a branch**, pick `main` and `/ (root)`, then save.
5. After a minute or two the site is live at `https://YOUR-USERNAME.github.io`.

## 3. Project repositories

1. Create `ldlr-ymi-thesis` and `pneumonia-amr-rajshahi` (public).
2. Upload `projects/ldlr-ymi-thesis.md` as the README of the first repository and `projects/pneumonia-amr-rajshahi.md` as the README of the second. Rename each to `README.md`.
3. Add a short description and topics on each repository page (for example `bioinformatics`, `human-genetics`, `antimicrobial-resistance`).
4. Pin both repositories to your profile (**Customize your pins**).

## 4. Things to replace before publishing

- `YOUR-USERNAME` in all files
- `YOUR-LINKEDIN-ID` in `index.html` and `README.md`
- Confirm that you are comfortable with your email address being public

## Data safety

- Never upload patient-identifiable data, raw clinical records or unpublished patient sequences.
- Ask your supervisor before publishing anything from the LDLR thesis. Some journals count public preprints or data as prior publication.
- The manuscript is listed as "under review"; update that line when the status changes.

## Making it stronger later

- Add real code (alignment, variant filtering, plotting scripts) to the project repositories and keep commits regular.
- Add figures you are allowed to share, such as a protein structure image of a published variant.
- Add your ORCID and Google Scholar links once you have them.
